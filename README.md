# LL8

Репозиторий-дистрибутив модпака **LL8** — чистой сборки
**TNP Limitless 8** (Minecraft 1.21.1, NeoForge) для лаунчера LANMinecraft.
Это единственный источник правды для лаунчера: клиенты получают пак не из git,
а из ассетов rolling-релиза `pack-latest`, который автоматически собирает CI.
Лаунчер находит источник по маркеру `portable-pack-source.json` в корне
установленного пака:

```json
{
  "schemaVersion": 1,
  "owner": "MarkZamore",
  "repo": "LL8",
  "tag": "pack-latest"
}
```

## Структура репозитория

| Путь | Что это |
| --- | --- |
| `mods/` | Все jar-файлы модов (публикуются детерминированными zip-чанками) |
| `config/` | Конфиги модов, включая paxi-датапаки (один детерминированный zip) |
| `kubejs/` | Скрипты KubeJS сборки (один zip) |
| `defaultconfigs/` | Серверные конфиги по умолчанию (один zip) |
| `configureddefaults/` | Дефолтные настройки клиента (один zip) |
| `resourcepacks/`, `shaderpacks/` | Ресурспаки и шейдеры сборки (по одному zip) |
| `portable-pack.json` | Описание пака: `minecraftVersion`, `loader`, `clientJar` |
| `minecraft-1.21.1-client.jar` | Клиентский jar, на который указывает `clientJar` |
| `UPDATE-LOG.md` | Журнал обновлений (пишет `tools/update_ll8.py`) |
| `tools/` | Инструменты обновления и CI; в пак не входят |
| `.github/workflows/publish.yml` | Конвейер публикации релиза |

Каталоги `mods/`, `config/`, `kubejs/`, `defaultconfigs/`,
`configureddefaults/`, `resourcepacks/`, `shaderpacks/` — **управляемые**: при
каждом обновлении `tools/update_ll8.py` пересобирает их из свежего релиза LL8
на CurseForge. Ручные правки в них будут перезаписаны — постоянные изменения
делаются только через `tools/overlay.json`.

## Как обновлять пак

Одна команда:

```bash
python tools/update_ll8.py
```

Что она делает: находит последний релиз TNP Limitless 8 на CurseForge,
скачивает и проверяет по sha1 каждый файл (переиспользуя уже имеющиеся
локальные копии), пересобирает управляемые каталоги, накладывает оверлей,
обновляет `portable-pack.json`, прогоняет сканер зависимостей, пишет
`UPDATE-LOG.md` и `tools/ll8-state.json`, коммитит слайсами ≤1,2 ГиБ и пушит
в `main` — дальше CI сам перепубликует `pack-latest`.

Полезные варианты:

- `python tools/update_ll8.py --dry-run` — только показать диф (какие моды
  добавятся/удалятся/обновятся), ничего не меняя в чекауте;
- `--world <путь к миру>` — дополнительно проверить, не лежат ли в мире
  предметы модов, которые обновление удаляет (WARN; `--strict-world` делает
  это ошибкой);
- `--version 1.68.1` / `--file-id N` — поставить конкретную версию;
- `--wait-release` — дождаться пересборки релиза CI и проверить его
  (`tools/verify_release.py`).

**Код выхода 2** означает, что часть файлов авторы запретили скачивать через
API и локальной проверенной копии не нашлось. Чекаут при этом не тронут.
Скачайте перечисленные в `C:\Users\Oskar\Documents\LL8-work\reports\
<версия>-manual-downloads.md` файлы вручную в
`C:\Users\Oskar\Documents\LL8-work\manual\` и запустите команду ещё раз —
найденные файлы навсегда осядут в `LL8-work\cache\` и больше не понадобятся.

## Политика оверлея

Пак — строго чистая LL8. Единственные локальные отличия описаны в
`tools/overlay.json` и накладываются заново при каждом обновлении:

- **e4steam** (`tools/overlay/mods/e4steam-…jar`) — пин лаунчера для Steam
  P2P; никакой другой e4steam/e4mc jar в `mods/` не допускается;
- `config/simplebackups-common.toml`: `backupsToKeep = 6` (в LL8 по
  умолчанию 4) — строчная правка, остальной файл байт-в-байт как в LL8.

Новые постоянные отличия добавляются только туда же, в `tools/overlay.json`.
Если после обновления ключ tomlEdit пропал из конфига, инструмент выходит с
кодом 3 — обновите `tools/overlay.json` под новый формат.

## Как работает конвейер релиза

Workflow `Publish LL8 pack` (`.github/workflows/publish.yml`) на каждый push
в `main`:

1. `tools/scan_mods.py --mods mods --fail-on-issues --lenient-ranges` —
   проверка jar-файлов (дубли modId и отсутствующие обязательные зависимости —
   ошибка; нарушения диапазонов версий — предупреждение, апстрим LL8 так и
   поставляется);
2. `tools/generate_manifest.py --pack . --out dist --revision "$GITHUB_SHA"` —
   собирает `dist/assets/` и `dist/pack-manifest.json`:
   - `mods/` делится на 256 детерминированных zip-чанков (номер чанка — чистая
     функция имени jar, так что обновление одного мода меняет один чанк);
     «горячие» jar из `tools/hot-mods.json` публикуются отдельными ассетами;
   - каждый непустой корень `config/`, `kubejs/`, `defaultconfigs/`,
     `configureddefaults/`, `resourcepacks/`, `shaderpacks/` — один zip с
     фиксированными таймстампами (байт-в-байт одинаковый при неизменном
     содержимом);
   - имена ассетов включают первые 12 символов SHA-256 содержимого;
3. самопроверка `--verify-only` — повторное хэширование случайных ассетов;
4. публикация: старый релиз и тег `pack-latest` удаляются, создаётся новый на
   текущем коммите, ассеты загружаются партиями по 40 файлов с повторами при
   сбоях, и **последним** загружается `pack-manifest.json` — его наличие и
   есть признак завершённого релиза для лаунчера.

## Рост истории git

Jar-файлы большие, и каждая замена мода навсегда раздувает историю git.
`tools/update_ll8.py` следит за этим сам: после коммита он сравнивает размер
истории с порогом `--history-limit-gib` (по умолчанию 3 ГиБ) и при превышении
автоматически схлопывает историю в свежий корень (orphan-squash + force-push,
`--no-squash` отключает). Это безопасно, потому что клиенты никогда не читают
git-историю — они скачивают только ассеты релиза `pack-latest`, который CI
пересоберёт после force-push автоматически. Факт схлопывания фиксируется в
`UPDATE-LOG.md`.

## Что НЕЛЬЗЯ коммитить

В репозиторий попадает только содержимое пака. Локальный «мусор» из игровой
папки не коммитим никогда:

- `options.txt`, `optionsof.txt` и прочие личные настройки клиента;
- `saves/` — миры;
- `logs/`, `crash-reports/`, `hs_err_*.log`, `.mixin.out/`;
- `screenshots/`, `backups/`;
- `xaero/`, `XaeroWorldMap/`, `XaeroMinimap/` — карты Xaero (данные игрока);
- `local/`, `journeymap/` — локальные кэши модов;
- `servers.dat`, `usercache.json`, `usernamecache.json`;
- `.portable-pack-sync.json`, `portable-pack-source.json` — служебные файлы
  лаунчера (генератор манифеста дополнительно отфильтровывает их сам).

## Миграция мира с Infinity

Одноразовый перенос мира со старой сборки Infinity на LL8 выполняет
`tools/migrate_world_ll8.py` (удаление предметов отсутствующих модов с
отчётом и бэкапом, remap AllTheOres в аналоги LL8, сброс измерений кроме
overworld). По умолчанию — dry-run; подробности в его `--help`.

## Контракт со стороны лаунчера

- Лаунчер скачивает из релиза сначала `pack-manifest.json`, затем недостающие
  ассеты: `files[]` описывает целевые файлы (путь, размер, SHA-256), `assets[]`
  — какие ассеты какие пути покрывают (`covers[]`); ассеты вида `zipRoot`
  распаковываются с сохранением путей относительно корня пака.
- Для кастомных синхронизируемых паков лаунчер кладёт в корень установленного
  пака маркерный файл `portable-pack-source.json` (см. выше). По этому маркеру
  лаунчер понимает, откуда обновлять пак. Файл существует только на клиенте —
  в репозиторий и в манифест он не попадает.
